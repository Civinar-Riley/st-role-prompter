# 07 避坑清单

写代码前扫一眼，出问题时先查这里。每一条都来自本地真实项目的踩坑记录或官方文档的显式警告。

---

## 一、环境与 API

### 1. 不要假设任何全局函数存在

```javascript
// 好
if (typeof appendInexistentScriptButtons === 'function') { ... }

// 坏：换个酒馆壳 / 未装酒馆助手时直接报错
appendInexistentScriptButtons([...]);
```

酒馆助手官方文档明确警告：`getChatMessages('0-end')`、`getLastMessageId()` 这类写法在部分环境（如某些桌面壳）不存在。**每个 API 调用前都要探测。**

### 2. 不要自己定义 `triggerSlash` 等扩展函数

官方 FAQ 原文：快速回复失效时"检查并删除代码中的 `triggerSlash` 函数定义，避免覆盖扩展的函数"。同理不要定义 `eventOn`、`generate` 等名字。

### 3. `eventOn` / `getButtonEvent` / `getScriptId` 只能在脚本内用

官方文档标记为 🚫TavernHelper 的函数（`eventOn`、`replaceScriptButtons`、`getScriptButtons`、`getScriptId`、`getScriptName`、`appendInexistentScriptButtons` 等）**只能在前端界面或脚本 iframe 内调用**，原生插件里不可直接用。

### 4. 脚本运行在 iframe 里，`document` 不是酒馆页面

```javascript
// 好
const host = window.parent && window.parent !== window ? window.parent : window;
const doc = host.document;
doc.querySelector('#send_textarea');

// 坏：在 iframe 自己的文档里找酒馆元素，永远找不到
document.querySelector('#send_textarea');
```

`localStorage`、`innerWidth`、`getComputedStyle` 同理，要取 `host.` 的。

## 二、生命周期

### 5. 用 `$(() => {})`，不要用 `DOMContentLoaded`

官方文档原文：通过 jsdelivr 动态加载脚本时不会触发 `DOMContentLoaded`。

```javascript
$(() => { init(); });                          // 好
document.addEventListener('DOMContentLoaded', init);   // 坏
```

### 6. 卸载用 `pagehide`，不要用 `unload`

```javascript
$(window).on('pagehide', cleanup);   // 好
$(window).on('unload', cleanup);     // 坏
```

### 7. 初始化前必须清理旧实例

更新脚本后旧界面不会自动消失，会出现两套 UI 叠在一起。

```javascript
['rni-fab', 'rni-panel', 'rni-style'].forEach(id => doc.getElementById(id)?.remove());
```

真实项目还加了"实例 token"做双开保护：

```javascript
const TOKEN_KEY = '__RNI_ACTIVE_TOKEN__';
const myToken = `t${Date.now()}${Math.random().toString(36).slice(2, 9)}`;
// 新实例启动时：host[TOKEN_KEY] = myToken；打开面板前检查 host[TOKEN_KEY] !== myToken 就报警并拒绝
```

### 8. 先绑事件，再做初始化

任何初始化报错都不应该让入口按钮失效。

```javascript
registerScriptButton(togglePanel);   // 先绑
initUI();                            // 后初始化（出错只影响面板）
```

### 9. 最外层包 catch，失败要有可见提示

```javascript
(async () => { ... })().catch(e => {
  console.error('[角色名注入] 启动失败', e);
  try {
    const d = (window.parent && window.parent.document) || document;
    const f = d.createElement('button');
    f.textContent = '❗';
    f.title = '角色名注入启动失败：' + (e.message || e);
    d.body.appendChild(f);
  } catch (e2) {}
});
```

### 10. 聊天切换时重置缓存

条目数据是全局的不受影响，但如果缓存了角色卡/世界书相关内容，要监听：

```javascript
eventOn(tavern_events.CHAT_CHANGED, () => { state.cache = null; });
```

## 三、数据与 API 使用

### 11. 用新版 worldbook API，不要用 lorebook

`lorebook` / `lorebook_entry` 系列已全部 `@deprecated`。

### 12. `/sendas` 有正文丢失 bug

走 slash 管道发消息会出现"楼层发出但正文为空"。改用：

```javascript
await createChatMessages([{ name: '角色名', role: 'assistant', message: '正文' }]);
```

### 13. `getChatMessages` 的范围写法

```javascript
getChatMessages(-1)                      // 最新一条
getChatMessages('0-{{lastMessageId}}')   // 全部
getChatMessages('0-end')                 // ✗ 不存在这种写法
```

### 14. `{type: 'character'}` 在没打开角色卡时会 throw

```javascript
try { getVariables({ type: 'character' }); } catch (e) { /* 无角色卡 */ }
```

### 15. 注入的提示词只在当前聊天有效

`injectPrompts` 的注入是聊天级的，切换聊天文件就没了。要跨聊天需监听 `CHAT_CHANGED` 重新注入。

## 四、UI 实现

### 16. 事件绑定要用 `doc` 而不是 `document`

真实项目踩坑：日志用 `document.querySelector` 渲染，结果永远不显示。所有 DOM 查询统一用 `doc`。

### 17. 拖动别用 Pointer Events

部分 WebView 不支持。用 `mousedown/mousemove/mouseup` + `touchstart/touchmove/touchend`。

（例外：悬浮球在 `多功能生成器` 里用了 pointer 事件且工作正常，但为了兼容性统一用 mouse+touch 更保险。）

### 18. 拖动结束后会跟一个 click

松手时的 click 可能触发面板开关，表现为"拖一下就关了"。用位移阈值 + 时间戳拦截：

```javascript
if (moved) { setTimeout(() => { moved = false; }, 100); return; }
```

### 19. 样式选择器必须加前缀

```css
.rni-item { ... }     /* 好：带项目前缀 */
.item { ... }         /* 坏：污染酒馆页面 */
```

### 20. 面板内点击会抢走输入框焦点

注入函数里显式 `ta.focus()` + `setSelectionRange()` 即可解决（见 03 文档）。

**不能指望酒馆帮忙**：酒馆自身的"焦点保持"逻辑只对 `send_but`、`mes_continue`、`mes_impersonate` 等**白名单元素**生效，我们的面板元素不在白名单里，点击面板反而会取消酒馆的焦点保持状态。所以焦点归还必须由注入函数自己完成。

### 21. iframe 内 `vw/vh` 的基准不是酒馆页面

官方 FAQ：iframe 内 `vw/vh` 以楼层 iframe 为基准。悬浮窗要挂到酒馆主页面（`doc.body.appendChild`），不要放进 iframe 自己的 body。

## 五、命令与调试

### 22. slash 命令写错没有任何反馈

`triggerSlash` 遇到错误命令可能静默返回 `undefined`。不要凭记忆编命令，拿不准就查 `slash_command.txt`。

### 23. 命令里的文本含 `|` 或换行会破坏解析

`/setinput 徐渭：“a|b”` 会把 `|` 当管道。多行文本必须走 DOM 方案。

### 24. 别用 `alert` / `confirm` 做主要交互

部分酒馆环境会拦截原生弹窗。统一用面板内的自定义弹窗，`host.confirm` 只用于低频的"隐藏悬浮球"这类操作。

### 25. 日志用 `console.info`，不要污染用户控制台

真实项目的约定：正常日志 `console.info`，错误 `console.error`，并在面板里提供可折叠日志区，方便用户反馈问题时贴图。

### 26. 报错要走酒馆通知

用 `errorCatched(fn)` 包装，或自己 `toastr.error(...)`。用户不会去看 F12。

### 27. 快速回复（QR）可能替换掉整个输入栏

输入框的父容器叫 `#nonQRFormItems`——命名含义就是"QR **未**接管时显示的表单项"。用户启用快速回复的"替换输入栏"类功能后，`#send_textarea` 和 `#rightSendForm` 可能都不存在。

对策：输入框查找用降级链（`#send_textarea` → `#nonQRFormItems textarea` → `#send_form textarea` → `#form_sheld textarea`），入口按钮保留页面右下角的兜底位置。

### 28. 输入框元素是动态显隐的

`#send_but`、`#mes_continue`、`#mes_impersonate` 初始都带 `displayNone`，由 JS 按连接状态/消息状态控制。往 `#rightSendForm` 插按钮时不要依赖兄弟元素的可见性，插到 `#send_but` 之前即可（该元素始终在 DOM 里）。

### 29. 注入不会弹出自动补全菜单（这是好事）

直接赋值 `textarea.value` 不触发 `input` 事件（DOM 规范），所以注入不会意外唤醒自动补全。这是期望行为，不要为了"唤醒补全"而手动 `trigger('input')` 两次。

- [ ] 所有 DOM 操作走 `doc`（`window.parent.document`）

- [ ] 卸载监听 `pagehide`，清理了注入的 DOM 与样式
- [ ] 初始化前清理了旧实例
- [ ] 先绑按钮事件再初始化
- [ ] 最外层有 catch 且失败有可见提示

- [ ] 手机端（触屏）拖动与点击都测过
