## 一、输入区的完整 DOM 结构

来自 `public/index.html`（第 8084-8130 行附近）：

```html
<div id="sheld">
  <div id="sheldheader" class="fa-solid fa-grip drag-grabber"></div>
  <div id="chat"></div>

  <div id="form_sheld">                                    <!-- 输入区外壳 -->
    <div id="dialogue_del_mes">…</div>                     <!-- 删除消息的确认条 -->
    <div id="send_form" class="no-connection">
      <form id="file_form" class="wide100p displayNone">…</form>

      <div id="nonQRFormItems">                            <!-- ← 注意这个容器 -->
        <div id="leftSendForm" class="alignContentCenter">
          <div id="options_button" class="fa-solid fa-bars interactable"></div>
        </div>

        <textarea id="send_textarea" name="text" class="mdHotkeys"
                  placeholder="Not connected to API!"
                  autocomplete="off"></textarea>

        <div id="rightSendForm" class="alignContentCenter">
          <div id="stscript_continue" …></div>
          <div id="stscript_pause" …></div>
          <div id="stscript_stop" …></div>
          <div id="mes_stop" …></div>
          <div id="mes_impersonate" …></div>
          <div id="mes_continue" …></div>
          <div id="send_but" class="fa-solid fa-paper-plane interactable displayNone" …></div>
        </div>
      </div>
    </div>
  </div>
</div>
```

要点：

1. `#send_textarea` 是**真 `<textarea>`**（不是 contenteditable），所以 `value`、`selectionStart`、`setSelectionRange` 全部可用。
2. 输入框的父容器是 **`#nonQRFormItems`**，命名含义是"快速回复（Quick Reply）**未**接管时显示的表单项"。用户启用 QR 的"替换输入栏"类扩展时，这个容器里的元素可能被替换掉。
3. 输入框右侧按钮区是 `#rightSendForm`，`#send_but` 是其中最右的发送键 —— 这验证了 `知识库/05` 里"把自定义按钮插到 `#send_but` 之前"的做法是对的。
4. `#form_sheld` 是更外层的容器，`#rightSendForm` 不存在时的降级位置。

**降级查找链**（写进代码里）：

```javascript
function findSendTextarea(doc) {
  return doc.querySelector('#send_textarea')                          // 常规
      || doc.querySelector('#nonQRFormItems textarea')                // 容器被换但结构在
      || doc.querySelector('#send_form textarea')                     // 再退一层
      || doc.querySelector('#form_sheld textarea')                    // 最后兜底
      || null;
}
```

## 二、官方自己怎么设置输入框文本（关键证据）

### 证据 1：`/setinput` 命令（`public/scripts/slash-commands.js` 第 3935 行）

```javascript
function setInputCallback(_, value) {
    $('#send_textarea').val(value || '')[0].dispatchEvent(new Event('input', { bubbles: true }));
    return value;
}
```

### 证据 2：`/impersonate` 流式写回（`public/script.js` 第 3677 行附近）

```javascript
if (isImpersonate) {
    this.sendTextarea.value = processedText;
    this.sendTextarea.dispatchEvent(new Event('input', { bubbles: true }));
}
```

### 证据 3：发送后清空输入框（`public/script.js` 第 4402 行）

```javascript
$('#send_textarea').val('')[0].dispatchEvent(new Event('input', { bubbles: true }));
```

**结论**：`设 value → dispatchEvent(new Event('input', {bubbles: true}))` 就是 SillyTavern **官方自己的唯一写法**，在三处核心逻辑中一致使用。我们的注入方案与官方实现同构，风险极低。

### 附带发现：`/setinput` 的光标行为

jQuery 的 `.val('...')` 会把光标重置到**文本末尾**，且 `/setinput` 内部没有任何 `setSelectionRange` 调用。这从源码层面证实了 `知识库/03` 的判断：**`/setinput` 无法控制光标位置**，不能用于本项目的核心场景。

## 三、自动补全不会干扰注入

`public/scripts/autocomplete/AutoComplete.js` 第 118-121 行：

```javascript
textarea.addEventListener('input', () => {
    this.selectionStart = this.textarea.selectionStart;   // 只读，不写
    if (this.text != this.textarea.value) this.show(true, this.wasForced);
});
```

两个关键结论：

1. **它只读光标，不重置光标**。所以我们在派发 `input` 事件之后（或之前）调用 `setSelectionRange` 都是安全的，不会被补全逻辑覆盖。
2. **`this.show()` 的前提是 `this.text != this.textarea.value`**。直接赋值 `textarea.value = ...` **不会**触发 `input` 事件（这是 DOM 规范），所以我们的注入**不会意外弹出自动补全菜单**——这正是我们想要的行为。

自动补全自己插入补全项时用的也是标准 API（第 722-724 行）：

```javascript
this.textarea.value = `${...}${this.selectedItem.replacer}${...}`;
this.textarea.selectionStart = effectiveStart + this.selectedItem.replacer.length;
this.textarea.selectionEnd = this.textarea.selectionStart;
```

**官方也是这么定位光标的**，等于给我们的 `setSelectionRange` 方案背书。

### 相关：输入框的 Markdown 快捷键不会干扰

`public/scripts/input-md-formatting.js` 里的格式化逻辑（`**粗体**`、`*斜体*` 自动配对等）**只监听 `keydown`**，不监听 `input`：

```javascript
textarea.addEventListener('keydown', …)   // 只在用户按键时触发
```

所以注入文本（不产生 keydown）不会触发任何 Markdown 自动格式化。

## 四、焦点保持逻辑与自定义面板的相互影响

`public/script.js` 第 11109-11125 行：

```javascript
//////////INPUT BAR FOCUS-KEEPING LOGIC/////////////
let S_TAPreviouslyFocused = false;
$('#send_textarea').on('focusin focus click', () => {
    S_TAPreviouslyFocused = true;
});
$('#send_but, #option_regenerate, #option_continue, #mes_continue, #mes_impersonate').on('click', () => {
    if (S_TAPreviouslyFocused) {
        $('#send_textarea').trigger('focus');     // 点发送键后把焦点还给输入框
    }
});
$(document).on('click', event => {
    if ($(':focus').attr('id') !== 'send_textarea') {
        var validIDs = ['options_button', 'send_but', 'mes_impersonate', 'mes_continue',
                        'send_textarea', 'option_regenerate', 'option_continue'];
        if (!validIDs.includes($(event.target).attr('id'))) {
            S_TAPreviouslyFocused = false;        // 点了白名单之外的元素，取消焦点保持
        }
    } else {
        S_TAPreviouslyFocused = true;
    }
});
```

对我们意味着什么：

1. **点击我们的面板/悬浮球，会取消酒馆的"焦点保持"状态**（因为面板元素不在白名单里）。这不是问题，但说明**我们的注入函数必须自己负责把焦点还给输入框**——`知识库/03` 里的 `ta.focus()` 是必需的，不能省。
2. **反向影响**：如果用户先点了输入框（`S_TAPreviouslyFocused = true`），再点我们的面板条目，`S_TAPreviouslyFocused` 会被重置为 `false`——因为我们的面板元素不在白名单里。所以不会出现"酒馆把焦点从面板抢走"的情况。
3. **潜在的时机问题**：如果我们在注入后立刻 `ta.focus()`，而酒馆的 `document` click 监听还在处理中，顺序上可能出现竞争。稳妥做法是把 `focus()` + `setSelectionRange()` 放在注入函数里同步执行（我们的实现已经是这样），并在必要时用 `requestAnimationFrame` 兜一次。

## 五、其他核实到的细节

### 5.1 发送时如何判定输入框内容

`public/script.js` 第 4401-4448 行：

```javascript
let textareaText;
if (…) {
    textareaText = String($('#send_textarea').val());
} else {
    textareaText = '';
}
…
if ((textareaText != '' || (hasPendingFileAttachment() && …)) && …) {
    await sendMessageAsUser(textareaText, messageBias);
}
```

**发送时是直接读 `$('#send_textarea').val()` 的实时值**，不依赖任何内部缓存。

这修正了 `知识库/03` 里"不派发 input 事件酒馆就认为输入框是空的、发不出去"的表述——**准确的说法是**：不派发 `input` 事件消息仍能正常发出（因为发送读实时值），但**输入框高度不会自适应、自动补全状态不同步、依赖 `input` 事件的扩展（含酒馆助手）收不到通知**。派发 `input` 事件是**为了兼容这些下游逻辑**，而不是为了"能发送"。

### 5.2 `#rightSendForm` 里的按钮会动态显隐

`#send_but`、`#mes_continue`、`#mes_impersonate` 初始都带 `displayNone` 类，由 JS 按状态（是否连接 API、是否有消息等）控制显示。

对我们的影响：**往 `#rightSendForm` 里插入自定义按钮时，不要依赖某个特定兄弟元素一定可见**，插到 `#send_but` 之前仍是正确做法（`#send_but` 元素始终存在，只是可能隐藏）。

### 5.3 输入框有 `mdHotkeys` 类

`class="mdHotkeys"` 标记它启用了 Markdown 快捷键。我们的注入不产生键盘事件，所以不受影响。
