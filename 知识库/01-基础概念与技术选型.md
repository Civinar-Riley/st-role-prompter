# 01 基础概念与技术选型

## 三种可选的开发形态

在 SillyTavern（酒馆）里加功能，有三条路：

| | 酒馆助手脚本 | 酒馆助手前端界面 | 原生插件（extension） |
| --- | --- | --- | --- |
| **本质** | 一段 JS，在酒馆后台常驻运行 | 一段 HTML+JS，渲染在某条消息楼层里 | 装在 `public/scripts/extensions/third-party/` 的扩展 |
| **有无界面** | 本身没有，但可以用 JS 往酒馆页面注入任意 UI | 有，但被限制在楼层消息区域内 | 有，可挂在设置面板 / 侧栏 / 任意位置 |
| **加载方式** | 酒馆助手 → 脚本库 → 新建脚本，粘贴代码，启用 | 酒馆正则把占位符替换为 `<body>` 包裹的 HTML | 扩展管理器 Install extension，填 Git 地址 |
| **依赖** | 需装酒馆助手（JS-Slash-Runner） | 需装酒馆助手 | 无额外依赖 |
| **开发难度** | 低，单文件即可 | 中 | 高，要处理酒馆模块 import 与版本兼容 |
| **典型用途** | 按钮、面板、悬浮窗、自动化 | 状态栏、剧情选项卡、角色卡 UI | 深度集成酒馆的功能扩展 |

### 关键区别：脚本能碰整个酒馆页面

酒馆助手脚本运行在一个 iframe 里，但它的 jQuery 是 `window.parent.$`，也就是说：

```javascript
// 在脚本里，$ 直接作用于酒馆主页面
$('body')            // 选中的是酒馆网页的 body，不是 iframe 的 body
$('#send_textarea')  // 能直接选到酒馆输入框
```

拿原生 DOM 也一样：

```javascript
const host = window.parent && window.parent !== window ? window.parent : window;
const doc = host.document;   // 酒馆主页面的 document
```

**这一条是"悬浮窗 + 注入输入框"能实现的基础。**

## 本项目选型：酒馆助手脚本

理由：

1. **需求本质是"常驻悬浮窗 + 操作输入框"**，不属于任何一条消息楼层，前端界面形态（楼层内 iframe）天然不合适。
2. **不需要跨版本维护酒馆模块 import**。原生插件要 `import { eventSource } from '../../../../script.js'`，酒馆更新容易断；脚本用酒馆助手封装好的稳定 API。
3. **分发简单**。脚本是一个 JSON 文件，用户导入酒馆助手即可，无需装扩展、无需重启。
4. **本地已有成熟范例**：`制作-角色生成加入世界书` 项目就是同形态（悬浮/居中面板 + 脚本按钮 + localStorage），整套骨架可直接复用。

代价与注意：

- 用户必须装酒馆助手（对目标用户群来说这是默认前提）。
- 脚本内可用的一批函数（`eventOn`、`getScriptId`、`replaceScriptButtons` 等）**只能在脚本 iframe 内用**，官方文档标记为 🚫TavernHelper；反过来在原生插件里这些函数不可直接用（要用 `TavernHelper.eventOn` 之类的全局导出）。

## 运行环境：脚本在 iframe 里

```
酒馆主页面 (window.top)
├── #send_textarea          输入框
├── #rightSendForm          输入框右侧按钮区（脚本按钮就渲染在这附近）
├── #extensions_settings2   扩展设置面板
└── <iframe> ← 你的脚本运行在这里
      window.parent = 酒馆主页面
      $ = window.parent.$  （jQuery 作用于主页面）
      document = 自己的 iframe 文档（一般不用）
```

推论：

- 所有 DOM 操作都要用 `doc = window.parent.document`，用 `document` 会找不到元素。
- `getComputedStyle`、`localStorage`、`innerWidth` 等也要取 `host.` 的，才能拿到酒馆页面的真实值。
- iframe 与主页面同源（无沙箱），所以可以直接互操作，无需 postMessage。

## 生命周期

```javascript
// 加载时执行：必须用 $(() => {})，禁止 DOMContentLoaded
// （通过 jsdelivr 动态加载的方式不会触发 DOMContentLoaded）
$(() => {
  init();
});

// 卸载时执行（用户关闭脚本 / 关闭酒馆页）：用 'pagehide'，不要用 'unload'
$(window).on('pagehide', () => {
  cleanup();
});
```

完整骨架（含环境等待与清理）：

```javascript
(async () => {
  'use strict';

  const host = window.parent && window.parent !== window ? window.parent : window;
  const doc = host.document;

  // 1) 等酒馆助手 API 就绪（轮询，15 秒超时）
  const t0 = Date.now();
  while (typeof triggerSlash !== 'function' && Date.now() - t0 < 15000) {
    await new Promise(r => setTimeout(r, 500));
  }

  // 2) 清理旧实例，避免更新脚本后新旧界面同时存在
  ['my-panel', 'my-style'].forEach(id => doc.getElementById(id)?.remove());

  // 3) 先绑定事件，再做初始化（初始化报错不会拖垮入口）
  registerEntry();

  // 4) 正式初始化
  initUI();
})().catch(e => {
  console.error('[角色名注入] 启动失败', e);
});
```

## 术语对照

| 文档里的说法 | 实际含义 |
| --- | --- |
| 酒馆助手 / Tavern Helper / JS-Slash-Runner | 同一个东西：`N0VI028/JS-Slash-Runner` 扩展 |
| 脚本库 | 酒馆助手里管理脚本的地方，分全局 / 预设 / 角色卡三类 |
| 脚本按钮 | 脚本声明的一排按钮，显示在输入框上方，点击触发 `getButtonEvent` 事件 |
| 前端界面 | 渲染在楼层消息里的 iframe 界面 |
| 楼层 / message_id | 聊天记录里的一条消息，从 0 开始编号 |
| 世界书 | World Info / Lorebook，关键词触发的设定条目 |
| 变量 | 酒馆助手的键值存储，有全局/预设/角色卡/聊天/楼层/脚本/扩展七种作用域 |
| STscript / slash 命令 | 酒馆的命令语言，形如 `/setinput 文本`，可用 `triggerSlash()` 执行 |
