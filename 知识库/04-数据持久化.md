# 04 数据持久化

## 七种变量作用域（酒馆助手）

```ts
type VariableOption =
  | { type: 'chat' }                                        // 绑定当前聊天文件
  | { type: 'preset' }                                      // 绑定当前预设，随预设导出
  | { type: 'global' }                                      // 绑定用户存档，全局可用
  | { type: 'character' }                                   // 绑定当前角色卡，随角色卡导出
  | { type: 'message'; message_id?: number | 'latest' }      // 绑定某条楼层消息
  | { type: 'script'; script_id?: string }                   // 绑定脚本，随脚本导出
  | { type: 'extension'; extension_id: string };             // 扩展私有
```

读写函数：

```ts
getVariables(option)                       // 读全部
replaceVariables(vars, option)             // 整体替换
updateVariablesWith(fn, option)            // 用函数更新（支持 async）
insertOrAssignVariables(vars, option)      // 存在即改，不存在即增
insertVariables(vars, option)              // 存在则不动
deleteVariable(path, option)               // 按路径删
getAllVariables()                          // 合并视图（全局→角色卡→脚本→聊天→楼层）
```

内置 lodash（全局 `_`），路径操作很方便：

```javascript
updateVariablesWith(v => _.set(v, '我的数据.条目', [...]) , { type: 'global' });
const 条目 = _.get(getVariables({ type: 'global' }), '我的数据.条目', []);
```

## 条目数据存哪：三个候选

| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| **全局变量** `{type:'global'}` | 跟随用户存档，跨角色卡/跨聊天都在 | 换设备不带走（除非导出存档） | **推荐默认**：这是"导演用的角色名速查表"，本来就该全局可用 |
| **脚本变量** `{type:'script'}` | 随脚本一起导出，分享给朋友时数据跟着走 | 换角色卡仍在，但用户不易察觉数据存在脚本里 | 适合"随脚本分发的预设条目包" |
| **聊天变量** `{type:'chat'}` | 每个聊天独立 | 开新聊天条目就没了 | 只适合"这一局专属的角色" |

**建议**：主存储用 `{type: 'global'}`，并在设置里提供"导出 / 导入 JSON"按钮，方便迁移与分享。想连数据一起分发时，再补一个"存到脚本变量"的开关。

## 推荐的存储结构

```javascript
// 全局变量里的样子
{
  "角色名注入": {
    "version": 1,
    "settings": {
      "triggerButtonName": "角色名注入",
      "showFloatingBall": true,
      "ballPosition": { "x": 1180, "y": 640 },
      "panelMode": "append",        // replace | append | cursor
      "sortMode": "manual"          // manual | recent | alpha
    },
    "groups": [                     // 分组（可空）
      { "id": "g1", "name": "主角团", "collapsed": false }
    ],
    "entries": [
      {
        "id": "e1",
        "name": "徐渭",
        "desc": "{{user}}，冷漠剑客",
        "group": "g1",
        "template": "徐渭：“|”",     // | 是光标落点标记
        "hotkey": "ctrl+1",
        "useCount": 12,
        "lastUsedAt": 1759999999999,
        "createdAt": 1759900000000
      }
    ]
  }
}
```

要点：

- `version` 字段用于将来做数据结构迁移。
- `template` 里的 `|` 是光标标记，比让用户填"光标在第几位"友好得多。
- `useCount` / `lastUsedAt` 支持"最近使用"排序，用起来会顺手很多。
- 条目 id 用 `builtin.uuidv4()` 或 `crypto.randomUUID()` 生成，避免改名后关联丢失。

## 读写封装（推荐写法）

```javascript
const STORE_PATH = '角色名注入';
const DEFAULT_DATA = { version: 1, settings: {...}, groups: [], entries: [] };

function loadData() {
  try {
    const all = getVariables({ type: 'global' }) || {};
    const saved = _.get(all, STORE_PATH);
    if (!saved) return structuredClone(DEFAULT_DATA);
    // 浅合并兜底，保证新增字段有默认值
    return {
      ...structuredClone(DEFAULT_DATA),
      ...saved,
      settings: { ...DEFAULT_DATA.settings, ...(saved.settings || {}) },
    };
  } catch (e) {
    console.error('[角色名注入] 读取数据失败', e);
    return structuredClone(DEFAULT_DATA);
  }
}

async function saveData(data) {
  try {
    await updateVariablesWith(v => _.set(v, STORE_PATH, data), { type: 'global' });
    return true;
  } catch (e) {
    console.error('[角色名注入] 保存失败', e);
    toastr?.error?.('保存失败，请检查控制台');
    return false;
  }
}
```

`structuredClone` 在部分 WebView 里可能不存在，可用 `JSON.parse(JSON.stringify(x))` 代替（数据是纯 JSON，无函数/日期对象）。

## localStorage 备选

如果不想污染酒馆变量（例如数据量大、或希望和酒馆存档解耦）：

```javascript
const host = window.parent && window.parent !== window ? window.parent : window;

function saveLocal(key, data) {
  try { host.localStorage.setItem(key, JSON.stringify(data)); return true; }
  catch (e) { console.error(e); return false; }   // 空间不足会抛 QuotaExceededError
}

function loadLocal(key, fallback) {
  try {
    const raw = host.localStorage.getItem(key);
    return raw ? JSON.parse(raw) : fallback;
  } catch (e) { return fallback; }
}
```

注意：localStorage 用 `host.` 前缀，否则写进的是脚本 iframe 的存储，与酒馆页面隔离。

真实项目 `制作-世界书编辑器` 的教训：localStorage 写入失败（空间不足）时**必须显眼告警并保持"未保存"状态**，否则用户以为存上了。

## 与 AI 的隔离

酒馆助手的 `{{get_global_variable::变量}}` / `{{format_global_variable::变量}}` 宏会**忽略所有以 `$` 开头的键**。如果将来需要把条目数据放在提示词可读的变量里、又不想让 AI 看到元数据，可以：

```javascript
{ "角色名注入": { "$meta": { /* 不给 AI 看 */ }, "可见数据": {...} } }
```

本项目的数据不需要发给 AI，正常存即可，知道有这个机制就够了。

## 变量管理器可视化

`registerVariableSchema(z.object({...}), { type: 'global' })` 可以给酒馆助手的"变量管理器"窗口提供校验与结构提示（不影响代码逻辑）。本项目数据结构简单，属于可选项。

## 数据迁移模式

```javascript
function migrate(data) {
  const v = data.version || 0;
  if (v < 1) {
    // 0 → 1：把旧的 text 字段改名为 template
    data.entries = (data.entries || []).map(e => ({ ...e, template: e.template ?? e.text ?? '' }));
    data.version = 1;
  }
  // 未来：if (v < 2) { ... }
  return data;
}
```

读出来先 `migrate()` 再使用，写完顺手 `saveData()`。
