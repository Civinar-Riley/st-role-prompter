# 角色提词器

> 仓库名 `st-role-prompter`　·　SillyTavern（酒馆）的快捷注入面板

给 SillyTavern（酒馆）用的**快捷注入面板**：把常写的角色名、台词格式、Markdown 格式存成条目，**点一下就注入到输入框，光标自动停在你要打字的位置**。

不用再手打角色名，也不用每次都敲一遍引号。

举例：点「徐渭」条目 → 输入框里出现 `徐渭：“”`，光标稳稳落在两个引号中间 → 接着打字就行。

## 安装使用

1. 打开酒馆 → 酒馆助手 → 脚本库 → 新建脚本
2. 把 [`dist/角色提词器-v1.2.1.json`](dist/) 的内容导入（或直接把 [`src/角色提词器.js`](src/角色提词器.js) 的代码粘进脚本内容）
3. 启用脚本，刷新酒馆
4. 点输入框上方的「角色提词器」按钮，或屏幕上的 🐧 悬浮球

**版本要求**：SillyTavern 1.18+ / 酒馆助手 4.x+。低于要求时脚本会提示升级并停止。

### 面板怎么用

| 操作 | 说明 |
| --- | --- |
| 点条目 | 把「注入内容」送进输入框，光标停在 `|` 标记处 |
| 右上角 ＋ | 新建条目 |
| 底部「预设库」 | 内置常用格式（对话双引号、心里话星号、Markdown 粗体/标题/链接…），勾选后加进通用池 |
| 底部「批量导入」 | 世界书扫描 / 批量粘贴名字列表 |
| 底部「日志」 | 展开运行日志（每步做了什么、注入成功/失败、保存结果），可一键复制——报问题时贴这个最有用。有未查看的错误时按钮会标红计数 |
| 右上角 ⚙ | 设置（注入方式、分隔符、自动收起、悬浮球、配色、导入导出、清空数据） |
| 条目上的 ✎ / × | 编辑 / 删除 |
| 悬浮球右键 | 隐藏（设置里可开回来） |
| Esc | 关闭面板或弹窗 |

### 条目 = 三段式

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| 标题 | 给你自己看：这是什么 | `徐渭` |
| 描述 | 给你自己看：更具体些（**不会注入**） | `{{user}}，冷漠剑客` |
| 注入内容 | 真正进输入框的东西 | `徐渭：“|”` |

`|` 是光标标记，注入时会被移除，光标停在那里。想注入一个真正的竖线就写 `\|`。不写标记时光标停在末尾。

### 三种注入方式

- **追加到末尾**（默认）——输入框空就直接填，非空就用分隔符接上（分隔符可选：另起一行 / 空一格 / 不分隔）
- **替换输入框全部内容**
- **插入到当前光标处**——先点输入框定位光标，再点条目。面板不会因为你点输入框而关闭

### 两个池子（重要）

| | 本卡池 | 通用池 |
| --- | --- | --- |
| 存在哪 | **角色卡自己身上**（角色卡数据的 `extensions` 字段） | 酒馆全局变量 |
| 可见范围 | 切到哪张卡显示哪张卡的 | 跨角色卡通用 |
| 分享角色卡时 | **条目一起带走** | 不带 |
| 更新角色卡时 | **会被新卡内容覆盖**（新卡没带就清空） | 不受影响 |

因为"更新角色卡会冲掉本卡条目"，**更新卡之前建议先在设置里导出本卡池备份**。

没有打开角色卡时（比如群聊）只能看到通用池，面板上会提示。

## 技术方案

做成**酒馆助手（JS-Slash-Runner）脚本**，原生 JS 单文件 IIFE，零构建零依赖。

核心技术点（已用官方源码核实，见 [`知识库/10`](知识库/09-输入框机制源码核实.md)）：

- 脚本运行在 iframe 中，但 jQuery 是 `window.parent.$`，可直接操作酒馆页面 DOM。
- 注入输入框：`#send_textarea` 改 `value` → `dispatchEvent(new Event('input', {bubbles:true}))` → `focus()` + `setSelectionRange()` 定位光标。**这是 SillyTavern 官方自己在 `/setinput`、`/impersonate`、发送后清空三处用的写法。**
- 酒馆对中文引号（`“ ”`）不做任何处理，Markdown 快捷键默认关闭——"光标停在引号中间"必须工具自己做。

### 数据安全

代码审查发现并修复过的两类丢数据问题，实现时都用机制挡住了：

- **保存失败回滚**（`mutateStore`）：改动 → 保存 → 失败就还原，不会留下"界面已改、磁盘没改"的幽灵状态。
- **切聊天/角色卡时关闭弹窗**（`storeStillValid`）：避免把改动写进已经过期的那份数据。
- **写盘串行队列**：避免快速连点时旧数据覆盖新数据。
- **只用 `insertOrAssignVariables`**，绝不用 `replaceVariables`（后者会整体替换变量表，清掉其他脚本的数据）。

## 开发

```bash
npm test        # 跑全部测试（157 项）
npm run build   # 构建 dist/
npm run check   # 语法检查
```

改完源码后 `npm test && npm run build`，再把 `dist/` 里的 JSON 导入酒馆验证。

**版本号只在源码里维护一处**（`src/角色提词器.js` 顶部的 `SCRIPT_VERSION`），构建脚本自动读取。

**脚本 id 跟着名称走**：`build.js` 把「名称 + id」存在 `.script-id` 里，名称变了就自动生成新 id（名称含版本号，所以每次发版都是一个全新脚本）。名称没变时重复构建会复用同一个 id，不会反复换。

> 换 id 不会丢数据——本工具的条目存在全局变量和角色卡变量里，不挂在脚本 id 上。
> 但**更新版本时记得把旧脚本停用或删掉**，两个版本同时启用会被双开保护挡住（会提示），界面上可能短暂出现两套入口。
